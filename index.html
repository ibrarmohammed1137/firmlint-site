How it works

Deterministic analysis. AI explanations. Proof before trust.

Standard analyzers find the issues. The AI layer helps engineers understand them. A verification loop decides which fixes are safe to show as verified.

1 · Analyze

cppcheck and clang-tidy check your code against MISRA, AUTOSAR, CERT and CWE rule sets.

→

2 · Explain

For each finding, the model writes a plain-English explanation specific to your code, a concrete risk statement, and a proposed fix.

→

3 · Verify

The fix is applied to a copy, re-analysed and compile-checked. Only fixes that pass are marked verified. The rest go to a human.

Why it's different

Most AI code tools trust the model. We don't.

Fixes that look right are not the same as fixes that are right. Firmlint checks each one before it reaches a reviewer.

Unverified AI suggestions

  • Accepted on how plausible they look
  • Can silence one finding and create two more
  • Often fail to compile in the real build

Firmlint

  • Re-applied to a copy of the file
  • Re-analysed with the same tool
  • Compile-checked before a verdict
  • Marked verified only when all three pass; otherwise left for a human
